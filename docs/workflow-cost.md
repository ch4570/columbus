# 도구와 명시적 탐색 정책의 완료 비용

이 평가는 응답 바이트 절약을 모델 비용 절약으로 바꾸어 말하지 않는다. 같은 근거 품질을 통과한 작업에서 도구 제공과 짧은 탐색 정책의 효과를 나눠 관측한다. [기존 RepoAtlas 0.4 관측](token-efficiency.md)의 이름·원본·수치는 그대로 보존한다.

## 무엇을 비교했나

| 조건 | Columbus | 추가 탐색 정책 |
| --- | --- | --- |
| A | 없음 | 없음 |
| B | 없음 | 알려진 파일 직접 읽기, 실패 시 전환, 근거 확보 후 종료 |
| C | 선택적으로 사용 가능 | 없음; 시작 명령을 강제하지 않음 |
| D | 선택적으로 사용 가능 | B와 같은 정책; 지원되는 경우 제한된 새 snippets 세션 |

목표·범위·권한·답변 형식·완료 기준과 효율적인 `rg`·소스 읽기는 모든 조건에 같다. B/D의 정책 본문도 동일하다. 이 실험은 사용자 의도를 제거하는 unharness 실험이나 필수 도구 호출 실험이 아니다. 도구를 사용할 수 있어도 직접 읽기로 끝내는 선택을 허용한다.

2026-09-09에 현재 로컬 설정의 `gpt-6-astra`, `high`를 요청했다. 이는 요청한 모델 별칭이며 공급자 내부 모델 배포의 증명은 아니다. Codex CLI 0.153.4, Python 3.14.7과 기존 parser 의존성을 사용했다. 이 모델과 가격을 제품의 영구 기본값으로 고정하지 않는다.

고정 합성 소스 230개에서 세 작업을 각 조건 두 번씩, 총 24회 계획했다. 순서는 사전에 회전·역순으로 배치했다.

- 알려진 Python 함수: CR/LF가 섞인 실제 줄과 문자열 안의 U+0085/U+2028/U+2029를 구분한다.
- 미지의 후보 탐색: 00~24 지역의 선언 25개를 모두 원문으로 확인한다. 첫 20개만 찾으면 실패다.
- Java·Python 동적 호출: 호출 계약·반사 생성·registry dispatch를 확인하고, 해결되지 않은 런타임 대상을 완전하다고 주장하지 않는다.

모든 필수 항목, 원문 위치, 최대 40줄의 정확한 연속 인용, 구조화된 사실, 완전성·한계 코드가 기계 검사를 통과해야 한다. 설명은 별도로 읽고 답변 해시와 연결한 검토 결과를 남긴다. 잘못된 함수, 빠진 후보, partial 그래프의 완전성 과장은 통과시키지 않는다. 작업을 마쳤다는 의미와 모든 런타임 동작을 확정했다는 의미도 구분한다.

## 관측 결과

**이번 관측에서는 비용 절감의 근거를 확보하지 못했다.** 24회 중 22회가 원문·사실 검사와 설명 검토를 통과했다. 2회는 Unicode 인용 실패였다. C/D의 12회에서도 Columbus 명령은 한 번도 실행되지 않았다. 따라서 도구 안내의 유무는 비교했지만 실제 도구·receipt·세션 예산의 경제적 효과는 측정하지 못했다.

아래는 실패까지 포함한 각 조건의 6회 전체 합계다. [공개 관측 자료](../evals/exploration/results/2026-09-09-workflow/controlled.json)에 24개 답변, 검토 결과, 원시 이벤트 해시와 집계를 함께 보존했다.

| 조건 | 성공/시도 | 전체 입력 토큰 | 그중 캐시 입력 | 출력 토큰 | shell 호출 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A | 6/6 | 422,545 | 280,320 | 9,548 | 11 |
| B | 6/6 | 437,712 | 297,216 | 9,521 | 12 |
| C | 5/6 | 422,350 | 256,640 | 9,646 | 12 |
| D | 5/6 | 451,812 | 280,064 | 9,988 | 13 |

네 조건이 모두 같은 품질을 통과한 묶음은 6개 중 5개다. 그 5개만 비교하면 추가 정책의 입력 변화는 도구 없는 B−A에서 −2.80%, 도구 안내가 있는 D−C에서 +8.42%였다. 방향이 일관되지 않으며 금전 절감률도 아니다. C−A는 −7.38%, D−B는 +3.31%였지만, 도구 자체를 사용하지 않았으므로 이를 Columbus 실행 효과로 해석하지 않는다. 위 전체 합계와 비교 대상이 다른 점에도 주의해야 한다. 예를 들어 A/B 전체 6회에서는 B가 A보다 입력을 3.59% 더 사용했다.

실패는 알려진 Python 함수의 두 번째 반복 C/D에서 발생했다. 함수 위치와 동작 설명은 맞았지만, 원문의 U+0085 등을 NUL이 포함된 다른 문자열로 바꿔 인용했다. 두 답변 모두 직접 소스를 읽었으며 Columbus는 사용하지 않았다. 이 오류를 도구 결함이나 동작 이해 실패로 단정하지 않는다. 실패한 두 시도의 **입력 154,083·출력 1,023토큰**도 전체 합계에 포함했다. 이 묶음은 동일 품질 비교에서 제외했고, 답변을 고쳐 쓰거나 유리한 결과가 나올 때까지 재실행하지 않았다.

본 실험 전체는 입력 1,734,419·출력 38,703토큰이다. 계측 필드 확인에 사용한 예비 호출 1회도 별도 공개했다. 예비 관측까지 합한 25회는 **입력 1,809,244·그중 캐시 입력 1,163,520·출력 39,162토큰**이다. 누락된 usage나 timeout은 없었다. shell의 비정상 종료 3건과 그 뒤 복구 작업은 숨기지 않았으며, 같은 명령 문자열의 재실행이나 별도 trial 재시도·위임은 없었다. 명령이 달라도 근거가 겹칠 수 있으므로 이것이 중복 탐색 전혀 없음의 증명은 아니다.

본 실험의 cold index 준비는 0.527초였다. 도구가 사용되지 않았기 때문에 재사용에 따른 회수 횟수는 판단 불가로 둔다. 시간 차이에 단순 산식을 적용한 값은 원자료에 구분해 보존하되 공개 보고서의 회수 결론으로 채택하지 않는다. 별도 예비 관측의 색인 준비 0.431초와, 최종 parser 변경을 감지해 모델 호출 전에 차단된 준비 0.552초도 관측 메모에 남겼다.

이 결과에 따라 알려진 파일 직접 읽기와 조건부 도구 선택을 유지한다. 도구·map·receipt를 필수 단계로 늘리지 않으며, 세션 예산은 선택적 로컬 통제로 남긴다. 이번에 확인하지 못한 대형 실제 저장소·수정/테스트 작업과 실제 세션 재사용의 경제성은 후속 관측 대상이다.

## 비용을 읽는 방법

입력에는 런타임이 보고한 시작 지침·도구 안내·대화 입력이 포함된다. 캐시 입력을 다시 더하지 않으며, 이미 출력에 포함된 추론도 다시 더하지 않는다. 실제 CLI의 `cache_write_input_tokens`와 `reasoning_output_tokens`를 각각의 세부량으로 정규화한다. 도구 출력 바이트와 shell 호출 수는 모델 입력이나 내부 모델 왕복 수가 아니다. 관측되지 않은 내부 왕복 수는 `unknown`이다.

실패·재시도·미완료 시도를 보존한다. 단가를 명시적으로 제공할 때만 서로 겹치지 않는 일반 입력·캐시 읽기·캐시 쓰기·출력 수량에 해당 단가를 곱한다. 사용량이 확인된 실패도 분자에 넣고, 고유하게 성공한 작업 수로 나눈다. 사용량·가격·위임 포함 범위를 알 수 없거나 성공이 0건이면 `cost_per_successful_task`는 `unknown`이다.

이번 실행에는 계정의 실제 요금표나 청구서를 제공하지 않았다. 따라서 토큰 증감과 실제 금전 절감은 구분한다. 실험 밖의 구현·독립 검토 에이전트 비용도 해당 CLI 이벤트에 나오지 않아 연구 전체 청구액은 알 수 없다. Columbus의 [세션 예산](../skills/columbus/references/session-budgets.md)은 자기 snippets 조회·stdout 전송량만 통제하며 이 전체 비용의 상한이 아니다.

## 해석과 남은 한계

합성 코퍼스 하나와 조건별 두 번의 읽기 전용 작업으로 실제 수정·테스트·대형 저장소·장기 세션의 생산성을 일반화하지 않는다. provider cache를 비우거나 cold라고 보장하지 않았고, 로컬 호스트 부하도 격리하지 않았다. 일부 코드 검증과 설명 검토가 같은 호스트에서 병행됐으므로 경과 시간의 작은 차이를 경제적 회수 시점으로 단정하지 않는다.

초기 색인을 별도로 측정하고 C/D에는 동일한 사전 생성 index를 제공했다. A/B에는 사용을 허용하지 않았으며, C/D도 실제로 호출하지 않았다. 고정 지침의 입력 비용은 매 시도에 포함돼 있다. 하네스의 단순 시간 기준 회수 산식은 금액 기준 손익분기점이나 통계적 보장이 아니며, 공개 단계에서는 도구가 사용되지 않은 조건의 회수 결론을 제외한다.

원문 인용·facts 검사는 강하지만 일반 자연어의 모든 진위를 자동으로 판정하는 것은 아니다. 조건별 성공률, 실제 도구 사용 여부, 실패 비용과 계측 누락을 함께 봐야 한다. 절감이 확인되지 않으면 그 결과를 그대로 남기며, 작은 관측에 맞추어 필수 탐색 단계를 새로 추가하지 않는다.

## 재현과 원본

[네 조건 실행·집계 절차](../evals/exploration/factorial-README.md)에 manifest, 고정 입력, 가격 계약, 실패·재시도·위임 처리와 재현 명령을 설명했다. CI는 모델 없는 parser·품질·집계 테스트만 실행한다. 실제 모델 호출은 별도로 실행해야 한다.

공개 자료에는 구조화된 측정값·답변·명령과 원시 이벤트 해시를 남기고, 원시 추론·stderr 로그는 로컬에 보존한다. 로컬 절대 경로는 표시용 라벨로 치환한다. 원본 capture·engine·fixture·실험 프로토콜은 로컬 보존본으로 다시 대조할 수 있다.

실험 후 Windows CI에서 확인한 프롬프트의 CRLF 해시 불일치와 전시 경로 구분자는 별도로 수정했다. macOS에서 완료한 관측 원본·판정·수치는 바꾸거나 재실행하지 않았다. 이전 관측은 보존한 당시 프로토콜로 검사하고, 수정된 하네스로 실행할 때는 새 코호트를 준비한다.
