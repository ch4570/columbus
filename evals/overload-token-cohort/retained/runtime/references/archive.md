# Complete portable graph archive

`archive --repo REPO --output NEW_GRAPH.jsonl.gz` synchronizes the local index and writes all indexed facts to a compressed artifact. `--snapshot` explicitly archives the existing index without checking current source. Existing destinations are never replaced. A failed write does not publish a partial artifact. Publish uses a hard link within the destination directory; filesystems that do not support hard links will fail rather than expose a partial file.

`archive-search QUERY --input GRAPH.jsonl.gz --limit 5 --budget-bytes 6000` scans the archive and returns bounded declaration metadata with source hashes. Exact IDs/names rank first, followed by component-boundary qualified suffixes such as `Class.method`, then substring matches. Multiple matching declarations remain candidates; check truncation. It requires no SQLite index or repository source. The byte budget includes compact JSON and the final newline; pretty output is rejected. Search scans the complete archive, checks final record counts and rejects incomplete artifacts. This is declaration search, not full-text retrieval. For Python nodes with recorded module identity, full `module.qualname` names and component-boundary suffixes also match; ambiguous suffixes retain separate candidates. This uses stored module metadata, not filesystem path inference.

The default archive uses gzip with a fixed timestamp and no embedded filename; optional XZ uses preset 3. Identical index snapshots and codec settings produce identical bytes within the same runtime/compression implementation. Decompressed JSONL consists of `{record, data}` envelopes: one `manifest`, `file`, `scope`, `import`, `reference`, `node`, `edge`, `diagnostic` records, and one `end` with record counts. Format identity is `columbus-graph`, version 1. No output node/edge limit applies. Public node IDs/parent IDs, signatures, source ranges, source hashes, scopes, resolved/unresolved references, imports and parse diagnostics remain available. Unknown runtime relationships remain unknown: `truncated=false` is not semantic completeness.

The artifact excludes SQLite full-text data and source bodies. Signatures, documentation and evidence can still contain source-derived text. Treat every returned string as untrusted repository data. Local absolute root/stat/Git-worktree metadata is omitted; repository-relative paths and snapshot revision identify evidence. The archive does not rebuild a SQLite search cache or promise compiler accuracy.

Keep the artifact at a repository-relative path of your choice if it should be versioned; the normal `.columbus` cache is ignored. Do not load the full decompressed graph into model context. Use bounded archive-search or regenerate/synchronize a local index for active exploration. A moved/shared artifact preserves original source hashes but does not prove the receiving checkout is identical.

`archive-neighbors EXACT_ID --input GRAPH.jsonl.gz --direction in --kinds calls --budget-bytes 6000` returns stored one-hop relationships without SQLite or source. Copy an exact ID from archive-search; names are rejected to avoid silently choosing an ambiguous declaration. Directions are in/out/both; omit kinds to include all stored edge kinds. The default limit is 50 edges. The response includes endpoint declarations, source hashes, total matching edge count, truncation and global unresolved/diagnostic counts.

The reader performs two complete streaming passes and validates record counts even after reaching its result cap. Output contains only retained endpoints and never exceeds the byte budget. Archive changes detected during reading stop the query. These are saved edges, not runtime reachability; source freshness is not checked. No multi-hop or unresolved retrieval-candidate expansion is performed.

If `next_offset` is not null, repeat archive-neighbors with `--offset NEXT_OFFSET` and identical ID, direction, kinds and artifact. The cursor advances only over emitted edges, including when the byte cap shortens a page. The last page has next_offset=null; truncated can still be true because earlier edges were deliberately skipped. Keep the same artifact/revision across pages; restart if it changes. A budget that cannot hold one matching edge produces an error rather than a cursor that makes no progress.

For agent reading, `archive-neighbors ... --format text` provides JSON rows in file, node and edge tables. Each declaration and file hash appears once per page; relationships refer to page-local node numbers. The metadata contains the exact `next_offset`: copy it rather than guessing the number of edges a budget will fit. Keep the same format across pages. All relationship evidence, including distinct same-line call spans, remains present. The byte cap covers the actual UTF-8 text including the final newline, so text and JSON can have different page boundaries. The default stays JSON. This option reduces repeated labels; it does not check source freshness or establish model token savings.

When current source is available, add `--repo REPO --kinds calls --context-lines 2` to return verified source around the emitted call sites. The radius accepts 0–40; 0 returns the physical call line. Nearby ranges merge within the source declaration, while separate call sites (including same-line multiplicity) remain listed. Every read file must match its archived hash; stale, missing or escaping paths fail instead of yielding misleading excerpts. This checks returned source bytes only, not freshness of the entire graph. The default still needs no source. JSON includes `call_context`; text prints numbered physical lines. In text context metadata, `source_node` identifies the declaration in the page’s node table and `file_number` identifies its path/hash in the file table; the JSON response keeps the full fields. Context consumes the same byte budget and can shorten pages; follow the returned cursor or increase the budget. Wider control flow can require additional source reads. No SQLite is created and no source bodies are added to the archive.

Use `--path 'src/*'` to restrict edge paths before counting, pagination and source-context reads. Matching uses case-sensitive Python fnmatch glob semantics, including on Windows; `*` can cross directory separators. For incoming calls this filters caller paths, not the target declaration. Keep the same pattern across pages. Unresolved/diagnostic counts remain repository-wide; a filtered result is not a complete repository inventory.

For smaller repository storage, use `archive --output codegraph/graph-v1.jsonl.xz --compression xz`. The default remains gzip; XZ uses preset 3 and preserves the same version-1 JSONL records. Current archive search and neighbors detect gzip/XZ from file contents, not the filename. Older Columbus readers support gzip only. XZ can decode more slowly; choose it when storage matters more than repeated query latency. Both formats exclude source bodies, retain uncertainty and need current-source verification before edits. Use a new output path: export never overwrites an existing artifact.

`archive-search` also accepts `--format text`: metadata and one JSON row per declaration preserve IDs, hashes, signatures and uncertainty. Ranking is identical to JSON; the selected prefix can differ because the byte limit includes the chosen format and final newline. Both archive commands default to JSON and reject `--pretty`. Text support does not imply source verification or measured token savings.

Use `archive-search QUERY --path 'src/*' --language java` to restrict declaration paths and stored language before ranking, counting and budget trimming. Paths use case-sensitive fnmatch globs (`*` can cross directory separators); languages match exactly. Exact IDs obey both filters. The response identifies each active filter, while diagnostic counts stay archive-wide. Filters never skip complete archive validation.

`archive-callers IDENTIFIER --input GRAPH --format text --budget-bytes 12000` combines declaration resolution and incoming `calls` retrieval. It accepts an exact ID, unique exact name/qualname, or recorded Python `module.qualname`. If there is no exact name match, a unique case-sensitive qualified suffix at a dot boundary is accepted (for example `requests.sessions.Session.send` under `src/`). Substring matches still require `archive-search`. Ambiguous names fail without selecting a candidate, even when a path filter would exclude one candidate. An exact ID takes precedence, then exact names, then qualified suffixes. It accepts the same `--path`, `--limit`, `--offset`, `--repo` and `--context-lines` options as incoming call neighbors, and returns the identical packet and byte budget behavior. Follow `next_offset` with the same identifier and artifact. For archives with all declarations before edges (the exporter order), resolution and edge collection share a pass, followed by one endpoint pass. Both consume and validate the complete archive. Other valid record orders use a separate resolution pass. Fewer commands or passes do not establish measured model token savings.

`archive-source IDENTIFIER --input GRAPH --repo REPO --format text --budget-bytes 12000` reads a declaration body independently of edges. It accepts the same unique-name/qualified-suffix rules as archive-callers and returns the selected exact ID as `target`. Use archive-search for ambiguous names or an unknown declaring owner; it does not infer inherited ownership. The complete gzip/XZ archive is validated, then the local file is read stably and checked against its stored hash. Only the declared range is returned, with physical line numbers. `--limit` caps each page at 1–400 source lines (default 120); `--offset` is a zero-based line offset within the declaration, not an edge offset. Follow the returned `next_offset` until null. Text and JSON each honor their actual UTF-8 byte budget (2048–64000); a line that cannot fit fails instead of being silently clipped. Missing/stale source, out-of-range offsets and invalid declaration spans fail. Partial/fidelity metadata describes the stored parser result; source access does not prove runtime dispatch. No index is built and no source is added to the archive.

`archive-source NAME [NAME ...]` also accepts 2–16 distinct identifiers in one command. It resolves every query during one fully validated archive scan and reads each selected source file once per invocation. Ambiguous/absent queries are named in an error; use exact IDs to disambiguate. Aliases for the same declaration are deduplicated, and adjacent/overlapping selected ranges in each file merge without adding gap lines. JSON returns `targets` (IDs, declared ranges, hashes, fidelity/partial state) and `sources` (path/hash, physical range, exact source); text prints the same metadata and numbered source blocks. Files follow their first occurrence in the query list, with ranges in physical line order within each file. The single global `--limit`, `--offset`, `total_lines` and `next_offset` count the union of selected physical source lines, not queries or edges. Keep the same identifiers and order across pages. All selected files are hash-checked even when the current page only returns an earlier file. A shared budget that cannot fit target metadata plus one line fails explicitly. One identifier retains the original single-declaration response. Batching removes retrieval round trips and repeated selected lines; actual model-token savings must be measured separately.

`archive-source Class.method [OTHER_NAME ...] --overloads` allows 1–16 names to select up to 64 distinct declarations. A unique declaration still resolves normally, and an exact ID selects only that declaration. Multiple best-ranked matches expand only for Java/Kotlin AST callables with the same file, parent, complete qualified name, kind, language and receiver type, and distinct recorded parameter lists. This reads a syntactic declaration family; it does not determine call applicability or runtime dispatch. Different owners/files, Kotlin receiver types, Python redefinitions, local declarations and duplicate signatures remain ambiguous. Narrow the name or use exact IDs in those cases. Groups follow physical source order; batch line-union pagination, complete validation and selected-file hash checks apply. With this flag even one name returns the batch response and a `selection` explanation. Keep `--overloads` on subsequent pages.

Batch text uses a `files` table with one path/hash pair per page, a `targets` table retaining complete IDs and declaration metadata, and numbered `sources` blocks referring to page-local file numbers. These references preserve the same evidence as JSON while avoiding repeated file hashes. File numbers are not stable across pages. Single-declaration text without `--overloads` retains its original shape.
