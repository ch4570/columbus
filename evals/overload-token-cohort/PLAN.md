# Prospective overload/routing actual-token cohort

This is a new, fixed six-pair cohort for the current Columbus package and skill. It does not overwrite the earlier six-pair failure or prior eleven failures. Development PRs may merge into `fix/ast-graph-evidence`; main/release PR #12 remains gated by actual input AND output savings with full quality and final-commit platform verification.

## Question and scope

The prospective hypothesis is that overload grouping, compact archive text, and task-appropriate routing may reduce repeated evidence delivery on related-method navigation. Measure the complete current package/skill versus efficient ordinary source exploration, not an isolated causal effect of one feature. Saved-archive trials have no writable SQLite, so they do not measure receipt continuation. Smaller packets, fewer commands, latency, cached-input reductions, and successful functional tests do not establish total-token savings.

Three distinct pinned source tasks: Gson `fromJson` routing/errors (Java), OkHttp `RequestBody` deprecated creation and body semantics (Kotlin), and Axios interceptor routing/order/errors (JavaScript). Use each complete pinned superproject ZIP, with identical source in both conditions and hashes/licenses retained. OkHttp's unrelated HPACK test-data gitlink is explicitly excluded; this is not a recursive checkout. The ZIP is the canonical byte corpus, including upstream export line endings. `sources.json` and each language's source receipt record requested/resolved URLs, pins and sizes. Oracle criteria and trial artifacts live outside model repository working directories; do not execute upstream code.

## Freeze before execution

Freeze sources, cases, all clause criteria, independent source reviews, source-citation positive/negative controls, representative graph controls, exact answer schema, current committed runtime/skill/references, XZ archive, preparation/runner/collector/recognizer/tests, environment and this plan before starting any model. `input-hashes.json` inventories required inputs and runtime files; source/runtime/archive manifests are independently checked before and after every trial. No model runs during controls.

Each task's four runs are sequential; task groups may run concurrently. No additional repeats, selective retries, source substitutions, prompt edits, exclusions of failed runs, or rubric relaxation after the first launch.
3. Preserve the existing saved-callers harness, `gpt-5.6-sol`, `xhigh`, 1200-second timeout, read-only sandbox, no web/delegation/repository execution, structured answer schema and bounded-evidence instruction. Model aliases are requested settings, not backend attestations. Codex CLI 0.153.4 supports JSONL events and output-schema; verified against OpenAI's official non-interactive documentation. No pricing inference from CLI authentication.
4. Preserve original prompts, invocations, process identities, raw JSONL, stderr, answers, terminal results and hashes. Monitor actual process handles; lack of a result is not a stopped process and is never retry permission. A timeout or model failure is retained as failure, not zero tokens. Fixed groups refuse existing trial directories.

## Full quality and strict acceptance

- Both arms must have exactly one completed turn, no terminal errors, valid actual usage, unchanged source/runtime/archive and exact protocol/prompt/schema. Every expected finding ID occurs exactly once, with no extra properties or findings.
- Each finding has one correct repository-relative path, a range of at most 40 physical lines containing its predeclared mechanism, and a contiguous verbatim quote within it (indentation ignored). The quote is representative evidence, not a requirement to fit every cross-file semantic clause into one range. Do not stitch distant excerpts. All criteria remain mandatory in the explanation and/or directly supporting quote; contradictory prose fails even if code is correct. Questions/descriptions explicitly request scored edge cases. No hidden requirement to audit excluded implementation internals.
- Independent answer reviews bind the answer SHA and frozen SOURCE-REVIEW SHA and mark every numbered criterion with boolean and reason. Review complete command traces against the read-only/no-web/no-delegation/no-upstream-execution/no-private-oracle restrictions; bind an `execution_review` to events SHA. A missing review is pending, never a pass. Auth/provider network traffic is not model web research.
- Columbus must actually issue a successful frozen-runtime/archive retrieval delivering task evidence. Use the prospectively frozen `archive-evidence-v1` recognizer; record batch use separately. It recognizes JSON and legacy/current compact text from a single Python invocation or one shell wrapper, not compound shell commands. Recognition proves neither source hash correctness nor answer quality by itself. An empty callers lookup does not count. Historical collectors remain untouched.
- In EVERY pair Columbus `input_tokens` (including its cached subset) must be strictly below baseline, AND `output_tokens` must be strictly below baseline. Cached input is a subset, not added again. Reasoning is an output subset when supplied. Missing/invalid usage, quality failures or either equal/increased token count reject the pair. No averaging or cross-pair compensation. All six pairs are required for cohort acceptance.
- Cohort acceptance alone is neither automatic release authority nor a universal savings claim. Main/release also needs all functional/distribution/platform gates at the final verified head/merge. If this cohort fails, retain and diagnose it, and continue development without reinterpreting it as acceptance.

The historical collector and its historical manifests are unchanged.
