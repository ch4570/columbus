# Predeclared source-level redirect criteria

Review every finding below against the fixed source revision in source.json. These are source semantics, not network execution or proof of subclass/adapter runtime dispatch. One bounded quote per finding is required by the harness; explanations may cover additional relevant source without requiring one oversized excerpt. Quotes can substantiate omitted detail, but contradicting prose fails. No model has run for this task.

- dispatch: Session.send delegates the initial send to an adapter and runs response hooks before redirect processing. allow_redirects defaults True there; enabled mode consumes the resolve_redirects generator and rearranges history/final response. Disabled mode still prepares r._next via yield_requests=True, without sending that next request. The redirect loop sends with allow_redirects=False; do not describe recursive uncontrolled redirect following. Non-stream mode consumes final content.
- method_policy: rebuild_method turns 303 and 302 into GET except HEAD; 301 changes POST only. Other methods/statuses remain unchanged, including 307/308. Do not equate all redirects with GET.
- body_retention: resolve_redirects calls rebuild_method, then removes Content-Length, Content-Type, Transfer-Encoding and sets body=None for statuses other than 307/308. This is a status condition, not merely a check that the method changed. The 307/308 path retains the copied body/entity headers.
- body_position: PreparedRequest.prepare_body recognizes streaming data separately from strings/lists/tuples/mappings. If tell exists, it records tell(); OSError stores an object sentinel rather than None. Explain that the sentinel allows later replay failure detection. Do not claim every stream is rewindable.
- body_rewind: resolve_redirects requires non-None _body_position plus Content-Length or Transfer-Encoding before calling rewind_body. The utility requires seek and an integer position, seeks to that position, translates OSError and otherwise raises UnrewindableBodyError. The object sentinel is non-None but not an integer, so failure is surfaced rather than silently replaying a consumed body.
- origin_auth_policy: different hostname strips authorization. Same-host standard-port http→https is a retained exception. Same scheme with explicit/default-equivalent ports retains; otherwise a scheme or port change strips. Do not generalize to keeping all same-host redirects or all upgrades, or stripping all scheme changes.
- auth_rebuild: existing Authorization is removed only when the policy requires it, using response.request.url and the new prepared URL. trust_env permits netrc lookup and non-None auth is prepared for the destination; this may replace/reapply auth, not just preserve the old header.
- proxy_selection: resolve_proxies copies the supplied mapping (None becomes empty). Environment proxies are considered only with trust_env and no bypass; scheme lookup falls back to all, and setdefault preserves an explicit scheme entry. A bypass prevents environment insertion here; this function does not erase existing explicit entries, despite broad docstring wording.
- proxy_auth: rebuild_proxies first resolves the mapping and deletes any existing Proxy-Authorization. It obtains credentials from the mapping's scheme key, treats a missing key as no credentials, and adds Basic only for non-HTTPS schemes with both username and password truthy. HTTPS handling is left to the adapter/urllib3; do not claim this header is always forwarded or recreated.
- cookies: the copied request's Cookie header is removed, response cookies are extracted with the previous request, session cookies are merged, and prepare_cookies rebuilds the header. After a redirect response is sent, session cookies are extracted again. Removing the header does not mean cookies are permanently discarded.
- redirect_url: while a redirect target exists, copy the request; consume response content with the listed decoding/runtime-error fallback, enforce max_redirects and close the response. Preserve prior fragment when the target has none; update it when supplied. Handle scheme-relative and relative targets, requote, and set the prepared URL. Refresh the target after sending. Do not claim yield_requests mode itself sends or advances a new network response.

Required guard/precedence statements above cannot be replaced by broad descriptions or docstrings. Unrelated cookie implementation details, full environment bypass algorithms, RFC conformance claims, network test results, and exhaustive adapter behavior are outside this task.
