# Portable AST navigation and commit-time updates

Install Columbus into an isolated Python 3.11+ environment, then run `columbus init --repo PROJECT` to install the managed agent skill. The engine, skill, and index have independent installation/update lifecycles. `init` does not install Git hooks or modify ignore rules. Ignore `.columbus/` in the target repository.

`tree --label NAME` emits JSONL: one metadata record followed by parent-first node records. Labels accept an exact ID, qualified name, or basename. Matching declarations include descendants and their containing ancestors, subject to `--limit`. Nodes carry IDs, parent IDs, source spans/hashes, fidelity, and `partial`. `scope_collapsed` means an internal scope without its own declaration node was traversed to the nearest indexed ancestor. `truncated` describes the output limit, not semantic completeness. Default trees contain only AST nodes (Python, Java, Kotlin); `--include-fallback` includes explicitly labelled heuristic/text nodes. Use `context ID` to read hash-verified source in a bounded response.

The persistent authority remains SQLite, with atomic snapshot updates. JSONL is an interchange/navigation projection: do not edit it to update the index. Saving a tree before a commit does not make it a representation of staged Git contents. Indexing reads files visible to the process, including eligible untracked files, and never stages or rewrites source.

For pre-commit framework users, add the repository's `columbus-sync` hook at a pinned revision containing `.pre-commit-hooks.yaml`. The hook installs the Python package into pre-commit's environment, passes no filenames, always runs (including deletion-only commits), and serializes invocations. Run pre-commit itself with Python 3.11+. Hooks see files after the framework's temporary stashing of unstaged tracked changes; untracked files can still be visible. Exploration auto-syncs after the framework restores files.

For a standalone local installation, `columbus hook-install --repo PROJECT --plan` shows the destination; omit `--plan` to install. Existing pre-commit files, symlink hooks, and configured `core.hooksPath` are preserved with an actionable conflict. Add `columbus hook-update` through the existing hook manager instead. Native hooks bind the installed Python interpreter and need reinstallation if that environment moves. Git's common hook directory is shared by linked worktrees; the hook uses the committing worktree's current directory, not the installation repository's absolute path.

`hook-update` reports compact JSON including `scope=visible_worktree`, counts, diagnostics, parse completeness, and `semantic_complete=false`. Parse recovery remains explicit and does not normally block a commit; process/index errors do. `hook-update --strict` rejects any diagnostic before replacing an existing snapshot. Strict mode checks parsing, not call-target correctness. Partial parses, external dependencies, overloads, and unresolved dispatch still require source review. Pre-commit refresh is a convenience: hooks can be skipped, and query-time synchronization remains necessary.
