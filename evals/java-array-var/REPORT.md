# Array-backed var loop bindings

Array loop bindings now infer var from the known element type of an array parameter or a validated enclosing loop array. Nested var array loops work; syntax facts retain var while the resolver derives an ephemeral binding. The original ten-case corpus resolves five of seven valid calls, up from four after explicit-array support. Getter/collection and generic-bound cases remain unresolved.

A targeted body-local class named Item exposed an incorrect naive inference: resolving an inferred Item name again inside the body could choose that local class rather than the array element declaration. Inference now requires the element identity to remain consistent across the enclosing and loop scopes. It conservatively rejects that valid shadowing case rather than selecting the wrong declaration. A related guard rejects treating a body-local class as the type of a formal array parameter; the explicit-type version of that program fails javac. Unknown/generic types, incompatible elements, local-name conflicts, and unsupported iterable sources retain the prior gates.

Four optional compiler controls extend the unchanged original ten sources: nested var, body-local type shadowing, invalid parameter/body type shadowing, and a generic var loop with an unrelated concrete T class. Both grammar environments pass all fourteen checks, with six of ten valid calls resolved and no wrong emitted target under the declared oracle. --var-controls requires the ordinary and nested var positive cases to remain resolved. Valid but unsupported calls remain counted as gaps. CI runs these controls alongside the explicit-array gate.

Both full engine environments pass 252 tests, root checks pass 53, the earlier 103-case compiler gate passes, and wheel/ZIP installation verification passes. Reindexing the same 1,166-file Spring corpus preserves all edges relative to explicit-array support (zero added, zero removed; source hashes match). No model trial ran and no real-corpus coverage increase or token savings are claimed. The broader collection, generic, local-array and field-array binding work remains incomplete.
