# Optional XZ graph archives

`archive --compression xz --output NEW.jsonl.xz` writes the existing complete version-1 JSONL records using XZ preset 3. Gzip remains the default. Readers detect gzip/XZ by magic bytes and preserve full-stream validation, bounded responses and source-independent queries. Unsupported or truncated XZ input is rejected. Legacy readers support gzip only; no existing artifact is rewritten.

Regression checks verify deterministic XZ bytes, exact decoded gzip/XZ byte equality, source/SQLite removal, equal search and incoming edge packets, distinct same-line calls, destination preservation and truncated-stream rejection. Both engine environments pass 222 tests. Clean wheel and ZIP installations exercise both codecs and compare query packets; local-distribution.json records their success. Root tests pass 53. An initial root determinism assertion overlapped edits to files packaged by that test; after edits stopped, the unchanged suite passed. The initial failure is not presented as a production compression defect.

The earlier identical-byte Django experiment measured approximately 19.9% smaller XZ-3 output with slower decode-plus-hash time; see ../call-span-storage/compression-probe.json. This release change establishes local functional support, not all-platform success or model token savings. Ordinary CI will run these expanded gates after push. No release was published.

## Full Django public CLI validation

verify_django.py exports the retained corrected Django database to both codecs and queries them through the public CLI from an otherwise empty consumer directory. Declaration search and all three 6,000-byte-budget incoming-call pages compare as complete JSON packets, preserving all 17 stored calls including same-line sites. Both archive hashes remain unchanged and no SQLite or other consumer files are created. django.json records exact checksums and receipts; temporary archives are deleted after validation.

Gzip is 10,726,317 bytes and XZ is 8,592,976 bytes. One search plus the three relationship pages took 7.47 seconds with gzip and 10.70 seconds with XZ on this unflushed host, sequential gzip-first execution. These are complete CLI query observations, unlike the earlier codec-only decode/hash timing. Keep gzip as the default for repeated querying; optional XZ offers lower repository storage with a measured read-cost tradeoff. This does not establish model token savings. The production source/SQLite is retained elsewhere but absent from the consumer directory; the tested archive commands do not use it.

The versioned-repository verifier now accepts --compression xz and retains gzip as its default. Both codecs pass locally, and XZ also passes with the candidate Java environment. The fixture creates a Git commit containing source and the graph, checks exclusion from source indexing, copies only the artifact, deletes the producer and queries from the moved consumer. versioned/ retains the XZ receipts. Ordinary CI now runs both variants across its six OS/Python jobs. Documentation distinguishes the minimum XZ-capable source revision from the older gzip-only pinned example. Platform success for this expanded versioned workflow is still pending.

## Saved-graph skill routing

The skill entrypoint now distinguishes a supplied/documented saved graph from a local index workflow. It directs archive-search and archive-neighbors before source reads in that case, avoiding an unnecessary local sync. It preserves source-hash verification, pagination and runtime uncertainty, and does not force archive discovery or loading for unrelated simple queries. Skill validation and the moved XZ producer-deletion workflow pass locally. This is instruction and command-flow validation; no model trial has yet established that agents follow this saved-graph route or save tokens with it. The reference's earlier gzip-only wording was corrected to cover optional XZ without promising byte identity across compression-library versions.
