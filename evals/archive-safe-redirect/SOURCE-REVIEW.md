# Pre-trial semantic criteria

The independent AST/import scan covers all 883 Python files under django/ and identifies three direct lexical calls in two owners. Both files import the public utility from django.utils.http at module scope. No matching receiver-method calls, alias rebinding or nested import ambiguity were found under the oracle's conservative assertions. The similarly named private helper in django/utils/http.py is a different target and is not a caller of the public function.

RedirectURLMixin.get_redirect_url (django/contrib/auth/views.py:43–53) obtains the configured redirect field from POST with GET as its default. POST key presence selects its value, including an empty value; this is not a truthiness fallback. It calls the utility unconditionally within the method, with the candidate, get_success_url_allowed_hosts() and request.is_secure(). The helper at lines 55–56 combines request.get_host() with success_url_allowed_hosts. The result is the original candidate if accepted, otherwise an empty string. get_success_url() can then use its default redirect, but is a transitive caller and must not be enumerated as direct. A caller explanation need not enumerate every subclass default redirect override.

set_language (django/views/i18n.py:30–74) obtains next from POST with GET as the default, again using key presence. The first validation runs only if next_url is truthy or the request accepts text/html. It passes {request.get_host()} and request.is_secure(). If that validation rejects the candidate, it substitutes HTTP_REFERER and validates that value with the same options; rejection of the second value selects '/'. The second call is conditional on first entering the rejection branch. If no next value exists and HTML is not accepted, validation is bypassed and a 204 response is selected. Otherwise a truthy resulting next value produces a redirect.

Its subsequent POST-only valid-language branch can translate the selected URL and replace the redirect when translation differs, and sets the language cookie. GET does not execute this state-changing branch. An answer claiming the initial redirect response is always final is wrong. Exact cookie option enumeration is not required by this redirect task, but any claims about those options must agree with source. The direct utility calls themselves are not POST-only.

The target tests allowed hosts and schemes; acceptance is not a blanket security guarantee. An answer may explain the target's empty-value rejection to clarify the fallback, but exhaustive implementation details of its private helper are not required. Do not confuse the caller's request.is_secure() argument with a universal requirement for absolute HTTPS URLs: relative paths can be accepted by the utility.

Acceptance requires the exact two lexical owners, citations covering their three direct call sites, and correct descriptions of the selection, short-circuiting and fallback behavior above. Source quotations can substantiate omitted detail but cannot repair contradictory prose. These criteria and the cases must be frozen before a model starts; no model trial has run.
