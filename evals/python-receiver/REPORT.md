# Python receiver coverage blocks the proposed multi-hop task

Before starting another model trial, the proposed incoming path from RepositoryIndex.symbol to read_stable was checked against the frozen source and saved graph. The AST contains `self._source(...)` at index.py:524, but its reference is unresolved. The subsequent `_source → read_stable → safe_source` edges exist. Thus the complete source-reviewed three-hop path is absent, and a graph-assisted answer would need source fallback at its first step. [Exact source/reference/edge evidence](real-path.json).

[Eight generated runtime traces](results.json) distinguish the coverage opportunity from unsafe shortcuts. Normal instance calls, static targets accessed through self, and a nested closure really reach C.helper. Reassignment, a subclass override, an instance-attribute replacement, a static method whose parameter happens to be named self, and a decorated target reach D.helper or a replacement instead. All eight current self.helper references remain unresolved. Run `PYTHONPATH=skills/columbus/scripts .venv/bin/python evals/python-receiver/observe.py OUTPUT.json` to reproduce; only literal fixtures execute.

This is not a newly fixed resolver or a passing multi-hop benchmark. It establishes why simply binding every self to its lexical class would introduce demonstrably wrong edges. Any implementation must preserve the distinction between source-based retrieval candidates and proven call targets, track shadowing/dispatch uncertainty, and retain these runtime counterexamples as negative gates. The real RepositoryIndex._source case is a static target, but that alone is insufficient: an instance or subclass can still replace that attribute.

No additional model trial was launched on a task whose reviewed path the graph cannot represent. The previous read_stable direct-caller token regression remains valid. The next implementation gate is receiver-aware candidate/path evidence with honest dispatch semantics, followed by a separately reviewed multi-hop quality oracle; token reduction and overall issue completion remain unproven.
