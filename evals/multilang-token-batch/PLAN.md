# Prospective multilingual actual-token release gate

The user explicitly confirmed that actual token savings belong to the release threshold. Existing functional success does not satisfy this requirement. Prior failed pairs and quality criteria remain unchanged; this new cohort is not a retry of the Django or Requests questions.

The implementation hypothesis is that fetching already known related declaration bodies together can replace serial graph/source reads and avoid overlapping source delivery. The skill now documents the batch command and continues to require contiguous verbatim citations and reading missing branches. The observed Requests trace had seven graph commands plus 24 ordinary commands, including rereads after archive-source; both caller lookups returned zero edges. Command counts/source bytes do not causally allocate model tokens. This cohort compares the resulting package/skill against ordinary efficient source exploration, not an isolated causal estimate of the batch feature.

## Fixed cohort and execution

- Three new real-source navigation tasks: Java property resolution in Spring, Kotlin ReflectionHints extension/Java delegation in Spring, and JavaScript template rendering in Express. The Kotlin task spans Kotlin and Java. Two tasks share Spring; this is two repositories, not three independent repository samples.
- Freeze each complete source snapshot, cases, all semantic requirements, citation markers, answer schema, runtime, skill, XZ archive, harness and protocol before any model starts. Verify marker controls, source hashes and archive/runtime gates first. Controls are not model answers.
- Six pairs: each task has two repetitions. Java and JavaScript run baseline then Columbus for repetition 1, then Columbus then baseline for repetition 2. Kotlin uses the opposite order. Each task's four executions are sequential; the three immutable task groups may run concurrently. No additional repeats, selective retries, dropped failures, source substitutions, prompt edits or rubric relaxation after launch.
- Use the existing saved-callers harness, gpt-5.6-sol with xhigh effort, identical 1200-second timeout, output schema, read-only restrictions and efficient bounded-evidence instruction in both conditions. The graph condition receives the frozen current skill and archive; baseline uses ordinary search and source reads. Requested model aliases are not provider backend attestations.
- Keep raw events, invocation/prompt/answer/result, terminal state and hashes. A live process is observed through its actual handle; an observation timeout never justifies restart. Model timeout/failure or missing usage fails acceptance and is retained, not scored as zero tokens.

## Acceptance: every pair must pass

1. Source, runtime, archive, schema, harness and frozen criteria remain unchanged. Exactly one completed model turn, zero terminal failures, source modifications or disallowed tools, and valid reported usage per execution.
2. Both answers contain exactly the requested finding IDs, each once. Every unchanged citation rule passes (required mechanism, correct file, at most 40 lines, contiguous verbatim source modulo indentation). Every predeclared semantic clause passes independent source review. Supporting quoted code can establish an omitted detail; contradictory prose fails. Source review does not require unsupported runtime claims or a full framework audit outside the declared question.
3. Columbus uses a successful graph retrieval delivering task evidence. Record batch use separately; merely offering the command or an empty callers response is not proof that batching produced savings.
4. Columbus total input tokens, including their cached subset, are strictly lower than baseline input; Columbus output tokens are also strictly lower. Cached/uncached input, reasoning subsets, command bytes, graph file size and latency remain separate. No cross-task or cross-repeat offsetting of failures. All six pairs must satisfy these same requirements.
5. Full engine, installer/archive, multilingual contract and final-commit platform gates also pass. Only then merge the verified PR head and publish 1.1.0 from the verified merge commit/tag workflow, and verify published assets. Actual token acceptance does not waive known functional failures.

Successful results establish only this predeclared cohort, not universal savings or complete semantics for every supported language. If any pair fails, record the failed gate and its diagnosed cause; do not merge/release or reinterpret functional success as token success.
